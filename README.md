# IEEE-CIS Fraud Detection

  •	Kaggle-ის კონკურსის მოკლე მიმოხილვა
  
პროექტი ეფუძნება Kaggle-ის შეჯიბრს [IEEE-CIS Fraud Detection](https://www.kaggle.com/competitions/ieee-fraud-detection) და მისი მიზანია განსაზრვროს, თუ რომელი ტრანზაქციაა fraud და რომელი არა. მოწოდებული dataset შეიცავს ათასობით ტრანზაქციას 400-ზე მეტი მახასიათებლით (feature-ით). სამიზნე კლასი ძალიან დაუბალანსებელია, ტრანზაქციების მხოლოდ 3.5% არის თაღლითური. შესაბამისად, შეფასების მეტრიკად გამოიყენება **ROC-AUC** და არა სიზუსტე.

  •	თქვენი მიდგომა პრობლემის გადასაჭრელად

ჩვენი მიზანია გავაკეთოთ ამ მონაცემების ანალიზი, გავასუფთავოთ დატასეტი არასაჭირო ინფორმაციებისგან, ძველ მახასიათებლებზე დაყრდნობით შევქმნათ ახალი მახასიათებლები, შევარჩიოთ საუკეთესოები და მათი გამოყენებით განსხვავებული პარამეტრებით დავატრენინგოთ რამდენიმე მოდელი - logistic regression → decision tree → random forest → AdaBoost → XGBoost. დავიწყებთ ყველაზე მარტივი წრფივი მოდელის ტრენინგით, შემდეგ დაგავალთ ერთი ხის არქიტექტურაზე, ამის შემდეგ კი ensemble მოდელებზე, ბეგგინგ-მოდელი - შემთხვევითი ტყე, ბუსტინგ-მოდელი - ადაბუსტი და ბოლოს გრადიენტიანი ბუსტინგი xg-ბუსტი. თითოეული მოდელი დატრენინგებულია არა მხოლოდ მისთვის საუკეთესო პარამეტრებზე, არამედ იმ პარამეტრებზეც, რომლებიც წარმოაჩენს under/over fitting-ს. თითოეული მოდელი საუკეთესო შედეგით დავარეგისტრირეთ პაიპლაინად, მათ შორის საუკეთესოს მივანიჭეთ champion სტატუსი და გამოვიყენეთ კონკურის საბოლოო შედეგის დასაგენენირებლად.

# Feature Engineering

  •	კატეგორიული ცვლადების რიცხვითში გადაყვანა

categorical სვეტები (`ProductCD`, `card4`, `card6`, `P_emaildomain`, `id_*` და სხვ.) მოდელის მიხედვით განსხვავებულად კოდირდება. 
logistic regression-ში გამოვიყენეთ სისხშირული კოდირება (frequency encoding), ანუ თითოეული კატეგორია იცვლება training სეტში მისი არსებობის სიხშირით (0-დან 1-მდე), რადგან ზოგადად წრფივი მოდელები უფრო კარგად მუშაობენ smooth რიცხვით კოდირებასთან. ყველა სხვა მოდელის დამუშავებისას გამოვიყენეთ oridnal encoding (ანუ თითოეული კატეგორია იცვლება მთელი რიცხვით (0, 1, 2...), რადგან ხეები ისედაც თავად იყოფიან threshold-ებზე და აქ მაგალითად one-hot encoding-ის გამოყენება არ იქნებოდა კარგი, რადგან ბევრ დამატებით მახასიათებელს კიდევ გააჩენდა.

  •	Nan მნიშვნელობების დამუშავება

logistic regression-ში რიცხვითი nan-ები შევცვალეთ median-ით და standard scaler გამოვიყენეთ სკალირებისთვის, ხოლო კატეგორიული nan-ებისთვის გამოვიყენეთ 'missing' სტრინგი. dt, rf, ada-შიც ასევე გამოვიყენეთ median რიცხვითი nan-ების შესაცვლელად და 'missing' სტრინგი კატეგორიულებისთვის (ამჯერად ordinal encoder-ით, როგორც უკვე აღვნიშნეთ), ხოლო xgboost-ში რიცხვითი nan-ები ხელუხლებლად დავტოვეთ, რადგან xgboost ტრენინგის დროს სწავლობს გამოტოვებული მნიშვნელობებისთვის ოპტიმალური split-ის მიმართულებას და მათი შევსება ამ მეთოდს ხელს შეუშლიდა, კატეგორიულებისთვის კი ასევე 'missing' სტრინგი გამოვიყენეთ (ordinal encoder).
მართ, ამიტომ მათთვის ეს გამოტოვებულია.

# Feature Selection

  ყველა ნოუთბუქში რამდენიმე თანმიმდევრული ნაბიჯი განვახლორციელეთ:

1. variance threshold

თუ ოდნავი ცვლილებებიც კი არაა ფიჩერი ვერც ერთ მოდელს ვერ დაეხმარება გადაწყვეტილების მიღებაში, ამიტომ ყველა მოდელის feature selection-ის დროს ის სვეტები წავშალეთ, რომლებიც თითქმის კონსტანტური ხასიათისაა, ანუ variance < 0.01.

2. correlation filter

logistic regression-ის feature selection-ის დროს გამოვიყენე კორელაციის ფილტრიც 0.95-ით, რადგან ამ მოდელისთვის კორელაცია კრიტიკულია, მაღალი კორელაცია რევს კოეფიციენტებს და მოდელი არასტაბილური ხდება. ხის მოდელებისთვის კორელაციის ფილტრი შეგვიძლია უგუვნებბელყოთ ხოლვე, რადგან ხეები, როგორც წესი, თავად ირჩევენ საუკეთესოს ორ თითქმის მსგავს ფიჩერთან მისვლისას, თავად იყოფიან, ამიტომ dt/rf ამით აღარ დავამძიმეთ, თუმცა მაინც გამოვიყენე ada და xg ბუსტინგის დროს, რათა თავიდან აგვერიდებინა პროცესის კიდევ უფრო შენელება. მართლაც, ბუსტინგის შემთხვევაში მაღალი კორელაცია ანელებს ტრენინგის პროცესს.

3. პილოტური მოდელი - Model-based Importance

ლოჯისტიკ რეგრეშენის გარდა, ყველა მოდელთან გამოვიყენე პილოტური მოდელი. ეს მოდელი ვარჯიშდება 50 000 ნიმუშზე და მნიშვნელოვნების ქულით საუკეთესო N ფიჩერი ინახება, რაც გვეხმარება იმაში, რომ ტრენინგის დრო დავზოგოთ და თან ეფექტურობაც შევინარჩუნოთ ყველაზე მნიშვენლოვან ფიჩერების გამოყენებით. ლოჯისტიკ რეგრეშენზე ეს საჭირო არაა, ასეთი მოდელზე დაფუძნებული მნიშვნელოვნება (Model-based Importance) მისთვის "ზედმეტია", რადგან აქ კოეფიციენტები თავად არიან ინდიკატორები, თავისი თავისი კოეფიციენტები აქვს და თუ მონაცემები ნორმალიზებულია, კოეფიციენტის სიდიდე პირდაპირ გეუბნება ფიჩერის მნიშვნელობას. თანაც აქ შეგვიძლია გამოვიყენოთ რეგულარიზაციასაც (მაგ. ლ1), რომელიც თავად "წაშლის" (ნულამდე დაიყვანს) უმნიშვნელო ფიჩერებს. ხის მოდელებში მსგავსი პილოტური მოდელი საქმეს პირიქით ამარტივებს.


# Training

ხუთივე მოდელზე გამოვიყენეთ **ფაზური hyperparameter ოპტიმიზაცია**: 
ერთი პარამეტრის ვარირება მეორეების ფიქსირებისას.
ვიწყებთ ბეის მოდელით და შესაბამისი განსხვავებული პარამეტრების ცვლით ნაბიჯ-ნაბიჯ ვიღებთ საუკეთესო შედეგს და ვავლენთ under/overfitting-ს.

ანუ საუკეთესო მოდელად შეირჩა **XGBoost** შემდეგი მიზეზების გამო:

**ყველაზე მაღალი val AUC** ყველა მოდელს შორის
**ყველაზე პატარა train/val gap**
**Early stopping** — overfitting-ს ავტომატურად ერიდება
**scale_pos_weight** — 3.5% fraud rate-ის დისბალანსი სწორად მუშავდება
**Native NaN handling** — numeric imputation არ საჭიროებს
**Gain-based feature importance** — უფრო სანდო feature selection

| სიმპტომი | მიზეზი | კონკრეტული მაგალითები |

| Train ≈ Val, ორივე დაბალი | **Underfitting** | LR (structural), DT_depth2, RF_n10, ADA_lr0001, XGB_depth3, XGB_lr0001 |
